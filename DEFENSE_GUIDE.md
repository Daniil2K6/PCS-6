# Линия защиты проекта - Система управления товарами на Blazor WebAssembly

## Общее описание проекта (1-2 минуты)

Это приложение для управления товарами интернет-магазина, разработанное на современном стеке технологий .NET. Проект состоит из двух основных частей:
1. **Клиент** - Blazor WebAssembly приложение, работающее в браузере
2. **Сервер** - ASP.NET Core REST API для обработки данных

## Архитектура решения (3-4 минуты)

### Почему мы выбрали эту архитектуру?

**Three-Tier Architecture:**
- **Presentation Layer (Клиент)** - Blazor WebAssembly обеспечивает интерактивный пользовательский интерфейс
- **Business Logic Layer (Сервер)** - ASP.NET Core обрабатывает запросы и бизнес-логику
- **Data Access Layer (БД)** - Entity Framework Core управляет доступом к данным

### Преимущества такой архитектуры:
✓ **Разделение ответственности** - Каждый слой отвечает за свою часть  
✓ **Масштабируемость** - Легко добавлять новые функции  
✓ **Переиспользуемость** - API могут использовать другие клиенты  
✓ **Тестируемость** - Каждый слой можно тестировать отдельно  
✓ **Безопасность** - Валидация на сервере, HTTPS, CORS  

## Технологический стек (2-3 минуты)

### 1. Blazor WebAssembly (Клиент)
```
Зачем: Создание интерактивного веб-интерфейса
Как: Код на C# компилируется в WebAssembly и работает в браузере
Преимущества:
- Полное приложение работает в браузере
- Моментальный отклик интерфейса
- Нет необходимости в постоянном соединении с сервером
```

### 2. ASP.NET Core (Сервер)
```
Зачем: Создание REST API для обработки данных
Как: Контроллеры обрабатывают HTTP запросы
Преимущества:
- Высокая производительность
- Встроенная поддержка асинхронных операций
- Простота тестирования
```

### 3. Entity Framework Core (ORM)
```
Зачем: Работа с базой данных через объектно-ориентированный интерфейс
Как: LINQ запросы вместо SQL
Преимущества:
- Безопасность (защита от SQL injection)
- Меньше кода для работы с БД
- Автоматическое отслеживание изменений
```

### 4. SQL Server (База данных)
```
Зачем: Надежное хранение данных
Как: Таблица Products с индексами для оптимизации
Преимущества:
- Надежность и высокая доступность
- Мощные возможности запросов
- Встроенная безопасность
```

## Ключевые решения и компромиссы (2 минуты)

### Решение 1: LocalDB вместо полного SQL Server
**Почему:** Удобство для разработки и тестирования
**Альтернатива:** В production использовать полноценный SQL Server

### Решение 2: Асинхронные операции везде
**Почему:** Лучша производительность и масштабируемость
**Результат:** Приложение может обрабатывать много пользователей

### Решение 3: Общая модель (Shared project)
**Почему:** Одна модель данных на клиенте и сервере
**Преимущество:** Избежать дублирования кода

## Обработка ошибок (1 минута)

```csharp
// На сервере - валидация всех данных
if (string.IsNullOrWhiteSpace(product.Name))
    return BadRequest(new { message = "Название товара обязательно" });

// На клиенте - информативные сообщения
if (editingProduct == null || string.IsNullOrWhiteSpace(editingProduct.Name))
{
    errorMessage = "Название товара обязательно.";
    return;
}
```

**Типы ошибок:**
- Валидация данных
- Ошибки сети
- Ошибки БД
- Исключения сервера

Все обработаны и показывают пользователю понятное сообщение об ошибке.

## Безопасность (1-2 минуты)

**1. CORS (Cross-Origin Resource Sharing)**
```csharp
options.AddPolicy("AllowBlazorClient", policy =>
{
    policy.WithOrigins("https://localhost:7279", "http://localhost:5279")
          .AllowAnyMethod()
          .AllowAnyHeader();
});
```
Разрешает только запросам с известных адресов.

**2. HTTPS**
- Все соединения зашифрованы
- Защита от перехвата данных

**3. Валидация на сервере**
- Не доверяем клиенту
- Все данные проверяются на сервере

**4. Entity Framework защита**
- Параметризованные запросы
- Защита от SQL injection

## Возможные вопросы и ответы (3-5 минут)

### Q: Почему Blazor WebAssembly вместо классического ASP.NET Razor?
**A:** Blazor WebAssembly позволяет:
- Код на C# выполняется в браузере
- Интерактивный интерфейс без перезагрузки страницы
- Работает и без соединения с сервером

### Q: Как вы обеспечиваете синхронизацию данных?
**A:** 
- HTTP запросы/ответы в формате JSON
- Каждая операция обновляет БД
- Клиент получает актуальные данные с сервера

### Q: Что произойдет если потеряется соединение?
**A:**
- На клиенте будет показано сообщение об ошибке
- Данные не будут потеряны (они в БД)
- Пользователь может повторить операцию

### Q: Как вы тестировали приложение?

- Проверка валидации данных

- Проверка работы в обеих темах

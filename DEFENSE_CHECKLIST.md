## 🔧 Технические вопросы и ответы

### Архитектура

**Q: Почему вы выбрали именно эту архитектуру?**

A: Three-Tier архитектура позволяет:
- Разделить ответственность между слоями
- Легко масштабировать каждый компонент отдельно
- Переиспользовать API для других клиентов
- Легко тестировать каждый слой
- Обеспечивает безопасность (валидация на сервере)

**Q: Как данные передаются между клиентом и сервером?**

A: 
- Клиент отправляет HTTP запросы (GET, POST, PUT, DELETE)
- Сервер обрабатывает запросы в контроллерах
- Данные сериализуются в JSON
- Сервер возвращает JSON ответ
- Клиент десериализирует JSON и обновляет UI

**Q: Зачем нужен Shared проект?**

A: Shared проект содержит общие модели (Product), которые используются:
- На сервере для работы с БД
- На клиенте для работы с API
- Это избегает дублирования кода

### Технологии

**Q: Почему вы использовали Blazor WebAssembly вместо стандартного ASP.NET Razor?**

A: Blazor WebAssembly позволяет:
- Писать весь код на C#
- Код выполняется в браузере (WebAssembly)
- Интерактивный интерфейс без перезагрузки страницы
- Меньше зависимости от сервера

**Q: Зачем нужен Entity Framework Core?**

A:
- Работа с БД через объекты вместо SQL
- Защита от SQL injection
- Автоматическое отслеживание изменений
- Генерация миграций БД
- Типизированные LINQ запросы

**Q: Как вы обеспечиваете безопасность?**

A:
- Валидация на клиенте (быстрая обратная связь)
- Валидация на сервере (основная защита)
- HTTPS для зашифрованной передачи
- CORS для контроля доступа
- Entity Framework защищает от SQL injection

### Особенности реализации

**Q: Как работает переключение темы?**

A: 
- ThemeService управляет состоянием темы
- Когда тема меняется, вызывается event OnThemeChanged
- Компоненты подписаны на этот event и вызывают StateHasChanged()
- CSS классы меняются в зависимости от темы

**Q: Как обрабатываются ошибки?**

A:
- На клиенте - try-catch блоки, показываем сообщения в UI
- На сервере - try-catch с логированием
- Асинхронные операции выполняются безопасно
- Пользователь видит понятные сообщения об ошибках

**Q: Как данные сохраняются в БД?**

A:
- Entity Framework Core отслеживает объекты
- При вызове SaveChangesAsync() генерируются SQL запросы
- SQL Server выполняет запросы и сохраняет данные
- Индексы оптимизируют поиск

### Дополнительные вопросы

**Q: Как вы тестировали приложение?**

A:
- Ручное тестирование всех CRUD операций
- Проверка валидации (пустые поля, отрицательные значения)
- Тестирование обработки ошибок
- Проверка работы обеих тем
- Использование curl/Postman для тестирования API

**Q: Какие следующие шаги развития?**

A:
- Аутентификация (Identity Server)
- Авторизация (роли пользователей)
- Поиск и фильтрация товаров
- Пагинация для больших наборов
- Категории товаров
- Отзывы и рейтинги
- Фотографии товаров
- Корзина и оформление заказа

**Q: Как вы обрабатываете отсутствие интернета?**

A: 
- Пока только показываем ошибку сети
- В будущем можно добавить:
  - Локальное кэширование (localStorage)
  - Очередь запросов когда соединение восстановится
  - Offline режим

**Q: Зачем все операции асинхронные?**

A:
- Лучшая производительность
- Не блокируем UI во время загрузки
- Сервер может обрабатывать больше запросов одновременно
- Современный стандарт веб-разработки

## 🚨 Потенциальные проблемы и решения

| Проблема | Решение |
|----------|---------|
| Сервер не запускается | Проверить порты, убить процессы, перезагрузить |
| Клиент не подключается к серверу | Проверить URL в appsettings.json |
| БД не создана | Сервер автоматически создаст её при первом запуске |
| HTTPS ошибка | Нажать "Advanced" и "Continue" |

| Тема не переключается | Проверить CSS в браузере, очистить кэш |
